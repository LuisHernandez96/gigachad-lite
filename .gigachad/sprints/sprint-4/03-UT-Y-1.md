## Description

RED tests for #8 (models default detection must read only the root TOML table and accept single-quoted strings) and #9 (run/wait/result --json must share one result schema).

## Plan

Class-level `@pytest.mark.red_phase`.

1. **#8** (`tests/test_models.py`), fake CODEX_HOME `config.toml` cases:
   - root `model = "gpt-6-sol"` then `[profiles.fast]` with `model = "gpt-5.5"` → default is `gpt-6-sol`.
   - no root model, only `[profiles.fast] model = "gpt-5.5"` → no default marked.
   - root `model = 'gpt-6-luna'` (single quotes) → default `gpt-6-luna`.
   - root model after a comment line and with trailing comment `model = "gpt-6-astra"  # main` → `gpt-6-astra`.
   - dotted/inline tables before the first `[table]` header are still root (only lines before the first `[...]` header count).
2. **#9** (`tests/test_cli.py`): run a claude-fake job with `run --json`, then `wait <id> --json`, then `result <id> --json`.
   All three outputs parse to dicts with the SAME key set, which includes at least: `id, state, agent, model, cwd, mode,
   exit_code, final_message, error, duration_s, killed_by, signal, depth, extras, stderr_path, job_dir, created_at,
   started_at, finished_at`. `extras.session_id == "sess-1"` and `duration_s` is a non-negative number. For a
   still-running job, `result <id> --json` exits 3 and prints the same schema with `state` running and null terminal fields.
