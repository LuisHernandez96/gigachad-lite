## Description

RED tests for lifecycle robustness findings #0–#4: group-wide SIGKILL escalation, persisted supervisor pid, reconciliation from result.json, worker cleanup on supervisor exceptions, and tolerant job listing.

## Plan

Class-level `@pytest.mark.red_phase` on new classes in `tests/test_jobs.py` (and `tests/test_cli.py` for #4 CLI).
Every test bounded (`store.wait(..., timeout=...)`, fail on TimeoutError); use `GIGACHAD_LITE_KILL_GRACE=1`.

1. **#0 group escalation**: extend the fakes with `FAKE_CHILD_IGNORES_TERM=1` — the fake spawns a child process
   (same process group) that ignores SIGTERM and sleeps 60s, records the child pid in FAKE_ARGS_FILE (or a pid file),
   while the fake itself exits on SIGTERM. (a) timeout=1 → job `timed_out` and the CHILD pid is dead within 5s;
   (b) supervisor SIGKILLed while running → `get()` finalizes `supervisor died` and the child pid is dead within 5s.
2. **#1 persisted supervisor pid**: immediately after `store.start(job)` returns, `meta.json` on disk contains a non-null
   `supervisor_pid` equal to the spawned pid. And: with the existing startup delay hook
   (`GIGACHAD_LITE_TEST_SUPERVISOR_DELAY=5`), SIGKILL the supervisor before it claims the job → `store.wait(id, timeout=10)`
   returns `failed` / `supervisor died` (no hang).
3. **#2 result.json recovery**: simulate a supervisor that wrote result.json (terminal `succeeded`, final message X) but
   died before updating meta.json (meta still `running`, dead supervisor pid). `get()` returns `succeeded` with final
   message X, and meta.json on disk is now terminal and matches result.json.
4. **#3 cleanup on exception**: add a test-only hook `GIGACHAD_LITE_TEST_FAIL_AFTER_SPAWN=1` (supervisor raises right
   after spawning the worker, before saving worker_pid). Run a FAKE_SLEEP=30 job → job ends `failed` with an error
   mentioning the exception, and no fake worker process remains (check via FAKE_ARGS_FILE pid / child pid file) within 5s.
5. **#4 incomplete job dirs**: create an empty directory under `<home>/jobs/` (no meta.json) plus one normal job →
   `store.list()` returns only the normal job; `gcl status` and `gcl list --all` exit 0; `gcl result <empty-dir-name>`
   exits 2 with "unknown job" (not a traceback).
