## Description

Fix lifecycle races #3–#6: honor cancellation before launch, never overwrite terminal records during reconciliation, kill orphaned workers when the supervisor dies, and treat zombie supervisors as dead while reaping owned children.

## Plan

1. **Per-job lock**: add a small `fcntl.flock`-based lock on `<job_dir>/.lock` used by every meta read-modify-write
   (supervisor state transitions, `get()` reconciliation, `cancel()`). Keep atomic `os.replace` writes.
2. **#3** supervisor startup: under the lock, reload meta; if already terminal or the `cancel` marker exists, record
   `cancelled` (if not already) and exit without launching the worker. Only then set `running` and spawn. After spawn,
   re-check the cancel marker immediately.
3. **#4** reconciliation in `get()`: under the lock, reload meta from disk after the liveness check; if terminal (or
   result.json exists) return it unchanged; only otherwise finalize as `failed`/`supervisor died`.
4. **#5** when finalizing a dead-supervisor job whose `worker_pid` is alive, SIGTERM the worker's process group, wait
   the kill grace, SIGKILL; record `killed_by: "supervisor_died"` and the signal used.
5. **#6** `pid_alive`: treat zombies as dead (Linux: read `/proc/<pid>/stat` state `Z`; macOS/other: `ps -o stat= -p`
   starting with `Z`). `JobStore` keeps the `Popen` handles it started in a dict and `wait()`/`get()` call `poll()` on them
   to reap owned supervisors.
6. Remove the test-only delay hook from any production code path other than the documented env check.
   Remove `red_phase` markers once green.
