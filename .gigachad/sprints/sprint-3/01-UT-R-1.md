## Description

RED tests for review findings #0, #1, #2 and #7: truly read-only Claude workers, non-blocking prompt delivery, separate stdout/stderr for result parsing, and an absolute job-store home.

## Plan

Class-level `@pytest.mark.red_phase` on new classes; use the `fake_agents` fixture and `GIGACHAD_LITE_KILL_GRACE=1`.

1. **#0 read-only claude** (`tests/test_adapters.py`): `--mode read-only` claude argv is exactly
   `["claude","-p","--model",M,"--output-format","json","--tools","Read,Glob,Grep","--strict-mcp-config", *extra]` —
   no `--dangerously-skip-permissions`, no `--disallowedTools`. Write mode unchanged.
2. **#1 stdin** (`tests/test_jobs.py`): extend fakes with `FAKE_NO_READ_STDIN=1` (never read stdin, then sleep
   FAKE_SLEEP). Start a codex job with a ~2 MB prompt, FAKE_NO_READ_STDIN=1, FAKE_SLEEP=30, timeout=2 → job ends
   `timed_out` within 10s (today it hangs). Also: cancel works for the same setup. Also: a normal large prompt (2 MB,
   fake reads stdin) is delivered intact (fake writes sha256 of stdin into FAKE_ARGS_FILE; compare).
3. **#2 stderr** (`tests/test_jobs.py`): extend the claude fake with `FAKE_STDERR="some warning"` (printed to stderr
   before the JSON). Job must be `succeeded` with the correct final message. The transcript/log must still contain the
   stderr text (either in `transcript.log` or a separate `stderr.log` that `gcl logs` also shows — assert via
   `gcl logs` CLI output containing both the JSON and `some warning`).
4. **#7 absolute home** (`tests/test_jobs.py`): `JobStore(Path("relhome"))` created while cwd=tmp_path has
   `store.home.is_absolute()`; env `GIGACHAD_LITE_HOME=relhome` (relative) + codex job with `cwd=<another tmp dir>` →
   `succeeded` and final message read correctly.
