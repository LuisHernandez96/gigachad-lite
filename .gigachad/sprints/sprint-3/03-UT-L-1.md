## Description

RED tests for job-lifecycle races #3 (early cancel), #4 (stale reconciliation overwrite), #5 (supervisor death leaves worker running) and #6 (zombie supervisor makes wait hang).

## Plan

Class-level `@pytest.mark.red_phase`. Every test must be bounded (use `store.wait(id, timeout=...)` and fail on
`TimeoutError`, never hang the suite). Make races deterministic with test hooks, not sleeps-and-hope:

1. **#3 early cancel**: add a test-only env hook `GIGACHAD_LITE_TEST_SUPERVISOR_DELAY=<seconds>` read by the supervisor
   at startup (sleep before launching the worker; document it as test-only). Start a job with delay 2 and a fast
   fake (FAKE_SLEEP=0), `cancel()` immediately → final state `cancelled`, the worker was never launched
   (FAKE_ARGS_FILE not created), and it stays cancelled after the supervisor exits.
2. **#4 stale overwrite**: unit-level — write meta `running` with a dead supervisor pid, then (simulating the supervisor
   finishing in between) have the on-disk meta become `succeeded` with a final message before reconciliation saves.
   Implement via monkeypatching the liveness check to rewrite meta.json to the terminal record and return False.
   `get()` must return `succeeded` with the final message and meta.json must still be `succeeded`.
3. **#5 orphaned worker**: start a codex job with FAKE_SLEEP=30; once running, SIGKILL the supervisor pid; `get()` →
   `failed`, error mentions `supervisor died`, AND the worker pid is dead within 5s (reconciliation killed the group).
4. **#6 zombie supervisor**: in the same process that called `store.start` (so the supervisor is our child), SIGKILL the
   supervisor; `store.wait(id, timeout=10)` must return a terminal job (not raise TimeoutError). Also unit-test the
   liveness helper: a zombie child (spawn `sys.executable -c "pass"`, don't reap, wait until it exits) is reported dead.
