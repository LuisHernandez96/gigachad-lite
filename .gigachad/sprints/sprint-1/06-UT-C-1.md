## Description

RED tests for the command-line interface (`gigachad-lite` / `gcl`): subcommands, JSON output, exit codes, recursion guard.

## Plan

`tests/test_cli.py`, class-level `@pytest.mark.red_phase`. Call `gigachad_lite.cli.main([...])` directly with
`capsys`, using the `fake_agents` fixture. Subcommands (every one accepts `--json` for machine-readable output):

- `start --agent {claude,codex} --model M (--prompt TEXT | --prompt-file PATH | --prompt-file -) [--cwd D] [--mode write|read-only]
  [--timeout S] [--name N] [-- EXTRA...]` → prints job id (text) or `{"id":..., "state":..., "job_dir":...}` (json); exit 0.
- `run` — same args as start, then waits; prints the result; exit code per the table below.
- `status [ID]` — no ID: jobs whose cwd == current dir (table: id, state, agent, model, age); with ID: one job.
- `wait ID [--timeout S]` — waits then prints result. `result ID` — prints result without waiting (exit 3 if not terminal).
- `logs ID [--tail N]` — prints transcript (last N lines). (`--follow` optional, not tested.)
- `cancel ID`, `list [--all]` (all dirs vs current cwd).
- Exit codes for `run`/`wait`/`result`: succeeded 0, failed 1, timed_out 124, cancelled 130, not finished (result) 3,
  unknown job 2, usage error 2.
- Text output of a result: first line `<id> <state> (<agent>/<model>, <duration>s, exit <code>)`, then the final message.
- Recursion guard: with `GIGACHAD_LITE_DEPTH=1` and default max depth 1, `start`/`run` exit 2 and print an error
  mentioning `GIGACHAD_LITE_MAX_DEPTH`; with `GIGACHAD_LITE_MAX_DEPTH=2` it proceeds.
- `--prompt-file -` reads stdin. Missing prompt → exit 2.
- `--version` still works.

Tests: one per bullet above, plus: `start --json` output parses and the job reaches `succeeded` via `wait --json`;
`run` with FAKE_RC=1 exits 1; `run --timeout 1` with FAKE_SLEEP=30 exits 124 (set GIGACHAD_LITE_KILL_GRACE=1);
extra args after `--` reach the fake's argv (FAKE_ARGS_FILE); `--mode read-only` for codex shows `-s read-only` in argv.
