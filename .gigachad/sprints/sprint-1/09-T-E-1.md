## Description

Package gigachad-lite as both a Claude Code plugin and a Codex plugin sharing one delegate skill, plus a zero-install bin wrapper.

## Plan

Repo root is the plugin root for both hosts. Formats below were verified against the installed codex CLI (0.159)
and Claude Code docs — use them exactly.

1. `.claude-plugin/marketplace.json`:
   `{"name": "gigachad-lite", "owner": {"name": "Luis Hernandez"}, "plugins": [{"name": "gigachad-lite", "source": "./", "description": "<one line>"}]}`
2. `.claude-plugin/plugin.json`: `{"name": "gigachad-lite", "version": "0.1.0", "description": ..., "author": {"name": "Luis Hernandez"}, "skills": "./skills/"}`
3. `.agents/plugins/marketplace.json` (Codex marketplace; same schema as #1).
4. `.codex-plugin/plugin.json`: `{"name": "gigachad-lite", "version": "0.1.0", "description": ..., "author": {"name": "Luis Hernandez"},
   "license": "MIT", "skills": "./skills/", "interface": {"displayName": "gigachad-lite", "shortDescription": "Delegate work to Claude or Codex workers", "category": "Productivity"}}`
5. `bin/gigachad-lite` and `bin/gcl` (POSIX sh, +x, committed executable): resolve the repo root from the script's own path
   (follow symlinks with a portable loop), then `PYTHONPATH="$ROOT/src${PYTHONPATH:+:$PYTHONPATH}" exec python3 -m gigachad_lite "$@"`.
   Claude Code puts plugin `bin/` on PATH, so no install is needed there.
6. `skills/delegate/SKILL.md` — frontmatter `name: delegate`, `description:` "Delegate a coding task to another AI agent
   (Claude via claude CLI, or OpenAI/Codex models via codex CLI) as a tracked background job with gigachad-lite. Use when
   the user asks to delegate, hand off, or get a second model to implement or review something." Body (host-neutral —
   it must read correctly inside Claude Code AND Codex):
   - What it is: execute-only. You (the orchestrator) own planning, verification, tests, review and git.
   - Setup: find the CLI — `gcl` on PATH; else `<directory containing this SKILL.md>/../../bin/gcl`; else
     `python3 -m pip install --user git+https://github.com/LuisHernandez96/gigachad-lite`.
   - Pick a worker: `gcl models --json`; if the user hasn't named one, ask them (offer a Claude model and a codex model;
     delegating across vendors is the point). Agent is `claude` for Claude models, `codex` for codex models.
   - Write a self-contained prompt file (the worker has none of your context): goal, relevant files, constraints,
     definition of done, "do not commit", and "finish with a short summary of what you changed".
   - Start: `gcl start --agent <a> --model <m> --prompt-file <f> --json` (add `--mode read-only` for reviews/second
     opinions; `--timeout` for long tasks). Record the job id.
   - Monitor: `gcl wait <id> --json` in the host's background/long-running command facility, or poll `gcl status <id>`
     periodically; keep the user updated (state, elapsed). `gcl logs <id> --tail 50` to peek. `gcl cancel <id>` to stop.
   - Finish: `gcl result <id> --json`; then VERIFY yourself — `git diff`, run the tests/linters — before telling the user it
     is done. If it failed or is wrong, refine the prompt and start a new job rather than hand-editing silently.
   - Parallelism: independent jobs may run concurrently in different directories/worktrees; never two writers in the same tree.
   - Recursion: workers cannot delegate further (depth guard); `GIGACHAD_LITE_MAX_DEPTH` raises the limit.
   - Exit codes table for `run`/`wait`.
7. `tests/test_packaging.py`: all four manifests parse; names/versions match `__version__`; `skills` paths exist;
   bin wrappers are executable and `bin/gcl --version` works via subprocess (no install); SKILL.md frontmatter has
   `name`/`description` and the body mentions `gcl start`, `gcl wait`, `git diff`, `--mode read-only`.
