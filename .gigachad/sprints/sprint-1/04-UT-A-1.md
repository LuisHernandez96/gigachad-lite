## Description

RED tests for the job store and detached supervisor: job creation, background execution, status transitions, timeout, cancel, stale-supervisor detection.

## Plan

`tests/test_jobs.py`, class-level `@pytest.mark.red_phase`, lazy import of `gigachad_lite.jobs`. Use the
`fake_agents` fixture (GIGACHAD_LITE_HOME in tmp). Poll with a small helper `wait_for(pred, timeout=10)` — never
fixed sleeps longer than needed.

Expected API (`gigachad_lite.jobs`):
- `JobStore(home: Path | None = None)` — default home from `GIGACHAD_LITE_HOME` or `~/.local/state/gigachad-lite`;
  jobs dir `<home>/jobs/`.
- `store.create(agent, model, prompt, cwd, mode="write", timeout=3600, name=None, extra_args=()) -> Job`.
  Creates `<home>/jobs/<id>/` with `prompt.md` and `meta.json` (state `queued`). Job id format
  `YYYYmmdd-HHMMSS-xxxx` (4 hex chars), unique.
- `store.start(job) -> Job` — spawns `[sys.executable, "-m", "gigachad_lite.supervise", job_dir]` detached
  (`start_new_session=True`, stdin DEVNULL, stdout/stderr → `<job_dir>/supervisor.log`), records `supervisor_pid`,
  returns immediately (< 1s even when the worker sleeps).
- `store.get(id) -> Job` (KeyError if missing; accepts unique id prefix), `store.list(cwd=None) -> list[Job]` newest first,
  filtered by cwd when given.
- `Job` fields (mirrored in meta.json): `id, name, agent, model, mode, cwd, timeout, depth, state, created_at, started_at,
  ended_at, supervisor_pid, worker_pid, exit_code, final_message, error` and `job_dir`. States:
  `queued, running, succeeded, failed, timed_out, cancelled`. `job.is_terminal`.
- `store.wait(id, timeout=None, poll=0.2) -> Job` returns when terminal; raises `TimeoutError` if wait timeout elapses.
- `store.cancel(id) -> Job` requests cancellation; job ends `cancelled` and the worker process group is gone.
- Supervisor (`gigachad_lite/supervise.py`) behavior, observed through the store:
  - runs the adapter command in `job.cwd`, prompt on stdin, stdout+stderr → `transcript.log`, own process group;
  - success rule: exit 0 AND non-empty final message AND not `is_error` → `succeeded`; otherwise `failed`
    with `error` describing why (e.g. `exit code 3`, `empty final message`);
  - `exit_code` is the worker's real exit code (never coerced);
  - timeout → SIGTERM process group, SIGKILL after 10s (make the grace configurable via env
    `GIGACHAD_LITE_KILL_GRACE` so tests use 1s) → state `timed_out`;
  - writes `result.json` = `{"id","state","exit_code","final_message","duration_s","agent","model","extras"}`.
- Reconciliation: if meta says `running`/`queued` but the supervisor pid is dead and no result.json exists,
  `store.get` reports `failed` with error `supervisor died`.

Tests (fake codex unless stated):
1. create → meta.json + prompt.md exist, state queued, id format.
2. start returns in < 1s with FAKE_SLEEP=3; state becomes running then succeeded; final_message == FAKE_LAST_MESSAGE;
   transcript.log contains `codex working`.
3. FAKE_RC=3 → failed, exit_code 3, error mentions exit code.
4. FAKE_NO_LAST_MESSAGE=1 with rc 0 → failed, error mentions empty final message.
5. Prompt containing `TASK_COMPLETE` + FAKE_NO_LAST_MESSAGE=1 → still failed (echo never counts).
6. timeout=1 with FAKE_SLEEP=30, KILL_GRACE=1 → timed_out within ~5s; worker pid no longer alive.
7. cancel during FAKE_SLEEP=30 → cancelled; worker pid no longer alive.
8. fake claude: FAKE_IS_ERROR=1 → failed; success path puts `session_id` into result extras.
9. Worker cwd is job.cwd (fake writes `os.getcwd()` into FAKE_ARGS_FILE — extend the fake if needed).
10. Stale supervisor: write meta with state running and a dead pid → `get` reports failed / `supervisor died`.
11. `list(cwd=...)` filters; `get` by unique prefix works.
