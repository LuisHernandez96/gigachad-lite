## Description

Record delegation depth on every job and attribute timeout/cancel kills with killed_by and signal fields, updating the CLI result line accordingly.

## Plan

1. Add one helper (e.g. `gigachad_lite/env.py` or inside `jobs.py`) `current_depth() -> int` that parses
   `GIGACHAD_LITE_DEPTH` (unset/empty → 0; malformed → 0 and a one-time warning to stderr naming the variable).
   Use it in `JobStore.create` (store `depth` on the Job + meta) and in `cli.check_depth`.
   Also parse `GIGACHAD_LITE_MAX_DEPTH` defensively (malformed → default 1 with a warning).
2. `supervise.py`: track which kill path fired and which signal actually ended the worker (SIGTERM if it exited
   within the grace period, else SIGKILL). Store `killed_by` and `signal` on the Job/meta and in result.json
   (null when not killed). Keep `exit_code = proc.returncode` exactly as reported — never coerce.
3. `cli.py` result text line: when `killed_by` is set, render `killed by <killed_by> via <signal>` instead of `exit <code>`.
   JSON output includes the new fields.
4. Update README "How it works" to mention `killed_by`/`signal`. Remove `red_phase` markers once green.
