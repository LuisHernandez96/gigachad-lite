## Description

RED tests for recording delegation depth on every job and for attributing timeout/cancel kills (killed_by, signal) instead of presenting the worker's post-SIGTERM exit code as the outcome.

## Plan

Mark new test classes `@pytest.mark.red_phase`. Use the existing `fake_agents` fixture and `GIGACHAD_LITE_KILL_GRACE=1`.

1. Extend `tests/fakes/codex` (and `claude`) with `FAKE_TRAP_TERM=1`: install a SIGTERM handler that prints
   `caught SIGTERM` and exits 0 immediately — this reproduces real codex behaviour. With `FAKE_IGNORE_TERM=1` the fake
   ignores SIGTERM entirely (so the supervisor must escalate to SIGKILL).
2. Depth (`tests/test_jobs.py`, new class):
   - env `GIGACHAD_LITE_DEPTH` unset → `job.depth == 0` and `meta.json["depth"] == 0`.
   - env `GIGACHAD_LITE_DEPTH=1` (and `GIGACHAD_LITE_MAX_DEPTH=5` so starting is allowed where relevant) → 1.
   - env `GIGACHAD_LITE_DEPTH=abc` → depth 0, no exception (store level), and `gcl start` does not crash (CLI level:
     treated as depth 0, job starts, a warning line on stderr mentions `GIGACHAD_LITE_DEPTH`).
3. Kill attribution (`tests/test_jobs.py`, new class):
   - timeout=1, FAKE_SLEEP=30, FAKE_TRAP_TERM=1 → state `timed_out`, `killed_by == "timeout"`, `signal == "SIGTERM"`,
     `exit_code == 0` (the worker's real code — not coerced), and result.json contains the same three fields.
   - timeout=1, FAKE_SLEEP=30, FAKE_IGNORE_TERM=1 → `timed_out`, `signal == "SIGKILL"`.
   - cancel during FAKE_SLEEP=30 with FAKE_TRAP_TERM=1 → `cancelled`, `killed_by == "cancel"`, `signal == "SIGTERM"`.
   - normal success → `killed_by is None` and `signal is None` (and the keys are present in result.json with null).
4. CLI text output (`tests/test_cli.py`, new class): for the timed-out job above, `gcl result <id>` first line matches
   `r"^\S+ timed_out \(codex/\S+, [\d.]+s, killed by timeout via SIGTERM\)$"`; for a normal success it still ends with
   `exit 0)`; for a failed job it still shows `exit <code>)`.
