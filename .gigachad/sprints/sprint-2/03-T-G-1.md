## Description

Add GitHub Actions CI with a single aggregate `ci` status check, plus CODEOWNERS and CONTRIBUTING, so main can be protected by rulesets.

## Plan

1. `.github/workflows/ci.yml`:
   - `name: CI`; `on: pull_request` (all branches) and `push: branches: [main]`.
   - Top-level `permissions: contents: read`; `concurrency: group: ci-${{ github.ref }}`, `cancel-in-progress: true`.
   - Job `test` with matrix `include`: {os: ubuntu-latest, python: "3.9"}, {os: ubuntu-latest, python: "3.12"},
     {os: macos-latest, python: "3.12"}; `fail-fast: false`; `timeout-minutes: 15`.
     Steps: `actions/checkout@v4`, `actions/setup-python@v5` (python-version from matrix),
     `python -m pip install -e ".[dev]"`, `ruff check src tests`, `pytest -q`.
   - Job `ci` (this exact job id AND `name: ci`) with `needs: [test]`, `if: always()`, `runs-on: ubuntu-latest`,
     single step that fails unless `needs.test.result == 'success'` — this is the one stable required check.
   - No secrets used; no `pull_request_target`.
2. `.github/CODEOWNERS`: `* @LuisHernandez96`.
3. `CONTRIBUTING.md`: fork the repo, branch, open a PR against `main`; direct pushes, force-pushes and deletions of
   `main` are blocked by repository rulesets; the `ci` check must pass; the maintainer merges (squash or rebase);
   run `pytest` and `ruff check src tests` locally first; keep the tool execute-only and stdlib-only.
4. README: short "Contributing" section linking CONTRIBUTING.md.
5. `tests/test_packaging.py` additions (text checks, no YAML dependency): ci.yml exists and contains
   `pull_request`, `permissions:`, `contents: read`, a job line `  ci:`, `needs: [test]`, `"3.9"`, `macos-latest`,
   and does NOT contain `pull_request_target`; CODEOWNERS contains `@LuisHernandez96`; CONTRIBUTING mentions `ci`.
